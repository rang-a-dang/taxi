Frames should be focused on the following question:
What does a mismatch between an artifact and code mean?

Various documents describe the frames differently.
Some are still using the rejected "distance" term, probably pulling in terminology from historical discussions.

explanatory → no action required; explanatory is a resource for factors to consider, reasons to account for, goals to evaluate against current goals

descriptive → the artifact has a bug (are we adopting the term "dud" to describe an artifact bug? If source code that produces incorrect behavior is considered to have a bug, then an artifact that produces incorrect behavior should have an analogous concept. AI is sort of like an artifact compiler.)

normative → there is work to do, and the code will ultimately change. It might be adding a new feature. It might be fixing an accidental bypass of the chosen architecture. It might be migrating modified code to a new technology or following a new convention.
