# normative/targets/ — what should become true

**Frame:** Normative — not-yet truth.

A target names a specific desired state that isn't true yet, so the gap between it and the present is visible as work.
It is existential and one-shot: once satisfied, it is done.
A target is a destination, not a route — the route is a plan.

## Reading rule

Never read a target as current state.
It describes the project as it should be, written in present tense precisely so that nothing needs rewriting when it comes true.

## Alignment rule

A target that differs from ground truth is at a **distance**, and that distance is legitimate: it *is* the work.
Close it by building toward the target, or re-aim deliberately — change the target and record why in a decision — never by silently editing the target to match what exists.
This frame is the only one where judgment chooses what changes: the project or the norm.

Editing a target to mirror what the project now does is a misfiling; that content is descriptive.

For a **pointer** (a target held in an external system), the same distance reading applies; you surface drift in the target's framing rather than editing the external source unilaterally.

## Lifecycle

A met target **converts**: it is discharged, and the new reality is recorded in the descriptive frame (the present-tense body usually carries over unchanged).
It does not linger here — a satisfied target left in `targets/` reads as outstanding work.
A target carries intent, not execution: no assignees, no progress, no tracker duties.

Per the root contract, converting or re-aiming is proposed, not performed unprompted.
