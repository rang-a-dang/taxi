# normative/plans/ — how we get from here to there

**Frame:** Normative — not-yet truth.

A plan is the route from the present to a target, or the standing process that keeps a constraint satisfied: the strategy, and the steps in order.
Where a target says *what*, a plan says *how*.

## Reading rule

Never read a plan's steps as work already done.
A plan asserts intended work, not current behavior.

## Alignment rule

A plan that differs from ground truth is at a **distance**: the un-walked part of the route.
Close it by executing, or revise the route deliberately if it proved wrong — never by silently rewriting the plan to describe what happened instead.

A plan records the route, not the progress along it.
Where the work stands is read by comparing the plan against reality (and against the tracker, if the team uses one) — it is not written into the plan.

For a **pointer** (a route maintained elsewhere), surface divergence rather than editing the external source unilaterally.

## Lifecycle

When a plan's route has been walked — the target it serves converts, or the process it describes is superseded — the plan is **removed**.
A finished plan left here reads as outstanding work.
Unlike decisions, a live plan may be edited freely as understanding improves.

Per the root contract, revising or removing a plan is proposed, not performed unprompted.
